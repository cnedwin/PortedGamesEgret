# A swarm of moving sprites from pooled rectangles, not shared-texture Bitmaps

At engine `b5628eb`, in headless Chromium with SwiftShader (no GPU), many `Bitmap`s sharing one small texture cost far more than rectangle sprites. In a 540 × 960 prototype for Nezha Stirs the Sea, 100 moving Bitmaps of one 48 × 48 texture from `textureFromCanvas` gave 33.3 ms p95, and 800 gave 66.6 ms p50, though they drew in about 2 `drawArrays` a frame. 200 moving `game.rect` sprites gave 16.7 ms p95, and 800 gave 33.4 ms. The profile was led by waiting on the GPU and by `getError`.

So a survivors-like with a hundred soldiers on screen cuts every moving thing from `drawRect` and keeps sprites of a kind in a pool:

```js
const pools = new Map();
const take = (key, make) => {
  const list = pools.get(key) ?? [];
  pools.set(key, list);
  const sprite = list.pop() ?? make();   // reuse before drawing a new one
  sprite.visible = true;
  return sprite;
};
const give = (key, sprite) => { sprite.visible = false; pools.get(key).push(sprite); };
const crab = take('crab', () => game.sprite((g) => g.beginFill(0xc8553d).drawRect(-12, -8, 24, 16).endFill(), layers.soldiers));
```

Rules:

- Measure first, with the same count the game reaches at its busiest; the game kept mid-game waves at 16.8 ms p95 and its cap of 140 soldiers at 33.3 ms.
- Draw a sprite's Graphics once when it is made; per frame, change only `x`, `y`, `rotation`, `alpha` and scale.
- Cap what is on the field in the rules, not the view, so the bot and the page agree.
- Rotated rectangles stay cheap; circles and paths that move do not (see moving-shapes).
