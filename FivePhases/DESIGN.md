# 《五行牌阵》/ FivePhases — 设计草案 v0.2

> 2D 卡牌 + 三消混合玩法 Demo，基于新白鹭引擎 Egret Rebuild。
> 状态：设计定稿，美术管线已跑通，**游戏本体未开工**（M1 起）。工作名原为《晶阵牌师》/ CrystalDeck。

---

## 0. 一句话定位

**下半屏消除攒能量，上半屏用卡牌打出去；消除本身会掉新卡，卡与卡之间的羁绊改变你的消除策略。**

对玩家的承诺（demo 要在 90 秒内交付的体验）：
> "我不是在玩消除，也不是在玩卡牌——我是在用消除的方式打一套卡组。"

---

## 1. 为什么这个组合能成立（机制咬合点）

卡牌+消除是最容易做成"两个游戏拼在一起"的组合。能不能成，取决于有没有**双向的因果**：

| 方向 | 机制 | 作用 |
|---|---|---|
| 消除 → 卡牌 | 消除某色方块，产出**该色**能量；能量只够打该色的牌 | 棋盘决策有了目的："我要打这张红卡，先得消红" |
| 卡牌 → 消除 | 卡牌技能会**改造棋盘**（染色、清行、生成特殊块、锁定格子） | 打牌不只是加伤害，而是在改自己下一步的棋盘 |

**只有单向因果（消除→伤害）会退化成"消除游戏带技能"**，这是绝大多数同类品的失败点。本方案把第二条方向作为硬性设计要求：**每一张非纯伤害卡都必须对棋盘产生可见影响。**

第二条缝合线是**视觉因果**：消除产生的能量球要沿贝塞尔曲线飞进对应的卡牌（0.25-0.35s），让玩家眼睛看到"消了 → 这张卡亮了"。这是 Empires & Puzzles 的核心手法，成本极低、效果极大。

## 2. 屏幕布局（竖屏，750×1624 设计稿）

```
┌─────────────────────────┐
│ 敌方舞台      28%        │  敌方立绘 ×1-3，血条，行动倒计时
├─────────────────────────┤
│ 我方舞台      20%        │  出战角色立绘（Spine 待机呼吸），技能演出区
├─────────────────────────┤
│ 手牌区        12%        │  5 张手牌，能量条叠在卡面
├─────────────────────────┤
│ 棋盘          32%        │  7×7 = 49 格
├─────────────────────────┤
│ 步数 / 回合   8%         │  剩余步数，结束回合按钮
└─────────────────────────┘
```

**关键比例决策**：棋盘只占 32%（约 500pt 高），而不是常见的 45-50%。原因：

- 二次元卡牌的卖点是立绘，立绘区（敌我合计 48%）必须给足，否则立绘只能是头像，动效也无处施展。
- 7×7 而非 8×8：单格约 68pt，手指友好，且 49 格在 500pt 高度内每格仍有 ~68pt，不会误触。
- 代价是棋盘偏小、可操作空间少。补偿方式是**每回合只有 3 步**，密度靠"每一步都重要"而不是"格数多"。

**为什么不做全屏切换**（消除一屏、战斗一屏）：
切换会切断"因果"。玩家消完看不到自己造成了什么，打牌时又看不到棋盘状态，两个玩法会彻底割裂。同屏常驻是这个设计不可让步的底线。

## 3. 核心循环

### 3.1 一次交换（0-2 秒）
拖动 → 高亮预览可消除格 → 交换 → 消除 → 下落 → 补充 → 连锁判定

### 3.2 一回合（10-25 秒）
1. 回合开始，抽 2 张（手牌上限 5），步数重置为 3，能量保留 2（上限 10）
2. 玩家自由穿插：消除 / 打牌（顺序不限，这是策略空间所在）
3. 每消除一次，敌方**行动倒计时 -1**
4. 倒计时归零 → 敌方攻击（棋盘短暂锁定 0.6s，敌人立绘前冲）
5. 步数用尽或玩家主动结束 → 回合结算 → 回到 1

**敌方行动用"倒计时"而不是"固定回合"**（借 Empires & Puzzles）：玩家能看到"再消一步敌人就打我了"，于是每次多消一步都是真实的赌博。这个紧张感比硬性回合制强得多，且几乎零成本。

### 3.3 一局（8-12 分钟）
```
选主角+初始 6 张牌 → 战斗1(小怪) → 三选一 + 强化 → 战斗2 → 三选一 → 精英 → 三选一 → Boss → 结算
```
局内构筑，单局结束即清空。**这是 demo 该有的形态**：自包含、无需服务器、无需长线经济，一局就能展示全部爽点。

## 4. 消除层设计（"爽感"的工程化）

爽感 = 可预期 + 超出预期 + 强反馈。三者缺一就变成"能玩但不上瘾"。

### 4.1 可预期（0 延迟）
- 拖动时实时高亮将被消除的格子（不做这一步，玩家会觉得"这游戏不听话"）
- 交换动画 ≤ 120ms，消除动画 ≤ 150ms，下落用重力曲线（快-慢-微弹）
- **绝不出现"我明明消了但它没反应"**：判定在交换确认的同一帧完成，动画是事后表演

### 4.2 超出预期（连锁）
- 连锁倍率：1 / 1.25 / 1.6 / 2.0 / 2.5 / 3.0
- 屏幕中央大字 `CHAIN ×3`，字号随连锁递增，颜色从白→金→红
- 每级连锁音效音高 +2 半音（这是最便宜、最有效的爽感放大器）

### 4.3 强反馈四件套（每次消除都要全给）
| 通道 | 做法 |
|---|---|
| 视觉 | 粒子爆发（8-12 颗，颜色随方块），方块缩放 1.0→1.3→0 消失 |
| 触觉 | 屏幕震动分级：3 消 2px / 4 消 4px / 5 消 6px / 特殊块组合 10px+80ms |
| 听觉 | 音效音高随连锁递升，第 5 连锁以上加一层"爆音" |
| 时间 | Hitstop 40-80ms（定格一瞬再继续），大招时 200ms |

### 4.4 特殊块（爽感的顶点）
| 触发 | 产物 | 效果 |
|---|---|---|
| 4 连 | 直线块 | 消整行/整列 |
| 5 连（直线） | 彩虹块 | 消全屏同色 |
| L / T 形 | 炸弹块 | 3×3 范围 |
| 双特殊块交换 | 组合 | 全屏清除 + 慢镜 + 白闪 |

**双特殊块组合必须是全场最爽的 1.5 秒**，所有预算（粒子、震动、慢镜、音效）都往这里堆。这是玩家会截图分享的瞬间。

### 4.5 消除产出
- 3 消 = 1 能量，4 消 = 2 能量，5 消 = 3 能量 + 特殊块
- 每 5 次消除掉 1 张卡（战斗中即时进手牌，稀有度由当回合最高连锁决定）
- 消除"万能块"→ 随机一张手牌费用 -1

## 5. 卡牌层设计

### 5.1 卡牌属性
| 属性 | 取值 |
|---|---|
| 元素 | 火/水/木/光/暗（对应棋盘 5 色 + 万能块） |
| 费用 | 1-4 能量 |
| 类型 | 攻击 / 防御 / 改造棋盘 / 召唤 / 增益 |
| 稀有度 | 普通 / 稀有 / 史诗（影响掉落权重与演出等级） |
| 羁绊标签 | 阵营、武器、元素、性格（用于羁绊判定） |

### 5.2 硬性设计约束（写进策划规约）
1. **每张卡的费用色 = 它需要的消除色。** 不许出现"任意色能量"的万能牌（除大招）。
2. **至少 40% 的卡必须改造棋盘。** 纯伤害卡不超过一半，否则第二条咬合线断掉。
3. 每张卡的文字描述 ≤ 2 行（竖屏卡面放不下更多）。

### 5.3 改造棋盘类技能示例（这是设计的灵魂）
| 卡 | 效果 |
|---|---|
| 烈焰斩 | 把最左一列全部染成火色 |
| 潮汐 | 清除最底两行，被清格必定掉水色 |
| 荆棘结界 | 在棋盘上生成 3 个"荆棘块"，消除它们才解锁相邻格 |
| 星轨牵引 | 把棋盘上所有万能块吸到中心 3×3 |
| 时间凝滞 | 本回合敌方倒计时暂停 2 步 |

## 5.5 元素系统：五行即五流派

### 元素必须同时干三件事

| 职责 | 说明 | 只做这一件的后果 |
|---|---|---|
| 视觉识别 | 棋盘上 5 色可区分 | 只是配色 |
| 策略归属 | 决定牌组构筑与能量分配 | 只是费用标签 |
| 世界观符号 | 玩家相信这个世界的力量来源 | 只是换皮 |

**反模式**：把「火水木光暗」改名叫「赤青碧金紫」，玩法一模一样。玩家两天就看穿，题材变成贴纸。
**正解**：元素从题材的**力量本源**推导出来，且每个元素有**独立的玩法人格**——不是"5 种颜色的同一种效果"。

### 主选：五行 = 五流派

五行的红利是**它自带相生相克**，而这套关系可以免费变成羁绊系统，玩家不需要学新规则就已经懂了。

| 元素 | 色 | 玩法人格 | 卡牌原型 | 战场职责 |
|---|---|---|---|---|
| 火 | 红 | 爆发直伤 | 高费高伤、连击增伤 | 主力输出 |
| 土 | 黄 | 护盾与反击 | 叠盾、盾转伤、嘲讽 | 承伤 |
| 金 | 白 | 破甲与暴击 | 无视护盾、暴击、斩杀 | 破防 |
| 水 | 蓝 | 控场与改棋盘 | 染色、清行、冻结、延后敌方行动 | 节奏控制 |
| 木 | 绿 | 持续与成长 | 中毒、回复、随回合成长 | 长线收益 |

五个元素 = 五套明显不同的打法，牌组构筑有了身份。这比"5 种颜色都能打伤害"高一个层级。

### 相生相克 → 免费羁绊

```
相生（顺位强化）：木→火→土→金→水→木
相克（属性压制）：木克土、土克水、水克火、火克金、金克木
```

- **相生做羁绊**：牌组里同时有「木」和「火」→ 木卡打出后，下一张火卡伤害 +50%（木生火）。玩家一看就懂，不用读说明。
- **相克做克制**：火属性敌人身上，火卡 -30%、土卡 +30%（土克水，水克火的反向同理）。
- **注意**：相克**只作用于卡牌伤害与敌方属性，绝不作用于棋盘掉落**。棋盘是随机的，玩家无法控制掉什么，把相克放进棋盘会变成纯随机惩罚。

### 两个必须解决的技术问题

**① 棋盘掉落要按牌组配比加权。**
纯随机掉落的致命问题：玩家组了全火牌组，棋盘上十分钟不掉一个火，直接卡死。解法是掉落权重向牌组的主要元素倾斜（例如主元素 30%、次元素各 18%、其余均分）。这条要在 `Board` 的补充逻辑里实现，且必须可配置——它是数值平衡的第一旋钮。

**② 5 色必须色盲可辨。**
红/绿是最经典的色盲冲突色对。解法：每个元素方块除了颜色还有**独立形状**（火=菱形、水=圆、木=叶、金=方、土=六边形）。这同时给引擎压测了 `textured-geometry-and-mesh2d` 这条路径。

### 元素在卡面上的三层标签

每张卡带三个独立标签，羁绊从三个维度交叉判定：

| 维度 | 例子 | 用途 |
|---|---|---|
| 元素 | 火 / 水 / 木 / 金 / 土 | 能量归属、相生相克 |
| 器物 | 剑 / 盾 / 符 / 丹 / 琴 | 组合技（剑+盾 = 剑盾同源） |
| 阵营 | 门派 / 散修 / 妖 / 器灵 | 合体技与共鸣 |

这样 30 张卡就能撑出足够的组合空间，且每个维度都有独立的叙事意义——不是硬凑的标签。

### 题材提醒

五行绑定东方题材（修真 / 山海 / 怪谈 / 志异）。**但仓库里的东方内容已经很重**：JY 金庸、Wulin 门派、SnowTemple 水浒、LanternShadows 西游皮影、Rally 醒狮长城。

如果要避开，元素得换一套推导。备选是「器灵」——器物成灵，五类器（刃/甲/符/丹/音）各自对应一种玩法人格，题材落在"现代都市 + 旧物有灵"，与现有内容不撞。代价是没有五行那样现成的相生相克，羁绊要自己设计。

**这是需要你拍板的第一件事。**

## 6. 羁绊设计（重点：组合，不是数值）

**反模式**：`同阵营 2 人：攻击力 +15%`。这是填充物，玩家感知不到，只会抄攻略。
**正解**：羁绊改变**操作策略**，让玩家主动调整消除顺序和出牌顺序。

| 羁绊 | 触发条件 | 效果 | 改变的决策 |
|---|---|---|---|
| 剑盾同源 | 剑卡 + 盾卡 | 打出盾卡的当回合，普攻额外造成"当前护盾值 50%"的伤害 | 先盾后攻，且会主动叠盾 |
| 三昧 | 3 张火卡 | 每累计打出 3 张火卡，免费触发一次全屏灼烧 | 会为了凑第 3 张而留牌 |
| 共鸣 | 同阵营 2 张 | 两人能量都满时，可耗尽全部能量发动合体技（双人 cut-in） | 会刻意攒双满能量，放弃单卡收益 |
| 残响 | 辅助卡 + 攻击卡 | 辅助卡使下一张攻击卡"再触发一次" | 出牌顺序变成核心思考 |
| 连锁体质 | 2 张以上"连锁"标签 | 连锁 ≥3 时全卡伤害 +30% | 会为了拉连锁而放弃眼前的好消 |
| 星轨 | 任意 2 张 | 消除万能块时，随机手牌费用 -1 | 会优先找万能块 |

**demo 只做 6 条羁绊、30 张卡。** 组合数已经够玩 10 小时，且平衡可控。

## 7. 数值框架（首版基准）

| 项 | 数值 |
|---|---|
| 棋盘 | 7×7，5 色 + 万能块（约 6% 出现率） |
| 每回合步数 | 3 |
| 能量 | 上限 10，回合开始保留 2 |
| 卡费 | 1-4，均值 2.2 |
| 手牌 | 上限 5，每回合抽 2 |
| 玩家血量 | 1000 |
| 敌人血量 | 小怪 600-1200 / 精英 2000 / Boss 4000 |
| 伤害基准 | 普攻卡 80 / 技能卡 200 / 大招 600 |
| 战斗长度 | 小怪 4-6 回合 / Boss 10-14 回合 |
| 敌方倒计时 | 3-5 步 |

**每回合期望产出校验**：3 步 × 平均 1.4 次连锁 × 约 4 格/次 ≈ 17 格 → 约 5 能量 → 可打 2 张牌。
即"每回合 2 次有效决策 + 3 次消除操作"，节奏合适，不会退化成无脑消。

## 8. 演出分级（成本控制的关键）

二次元卡牌的钱几乎全花在演出上。必须分级，否则做不完。

| 等级 | 时长 | 内容 | 适用 |
|---|---|---|---|
| L1 普攻 | 0.3s | 角色前冲 60px + 受击方抖动 + 飘伤害数字 | 所有普攻卡 |
| L2 技能 | 0.8s | 立绘局部放大 1.15× + 放射线背景 + 元素粒子 + 全屏轻震 | 稀有卡 |
| L3 大招/合体 | 1.8-2.2s | 全屏压暗 + 立绘入场（双人交错）+ 台词条 + 白闪 + 慢镜 + 强震 | 史诗卡、羁绊合体技 |

**立绘技术方案**：Spine 4.3（引擎已支持），每个角色 3 层——立绘主体（呼吸/待机循环）、表情差分（眨眼/口型）、特效层（刀光/法阵）。表情差分只做"正常/受击/施法"3 套，不要做 10 套。

## 9. 借鉴对象与取舍

| 借鉴对象 | 抄什么 | 别抄什么 |
|---|---|---|
| **Marvel Puzzle Quest** (2013) | **最接近的布局原型**：上方 3 张角色卡 + 下方消除，消除对应颜色给该角色充能，技能按色消耗 | 单局节奏偏慢，敌人回合冗长 |
| **Empires & Puzzles** (2017) | 上方英雄 + 下方棋盘；**能量球飞向卡牌的视觉缝合**；敌方按步数倒计时行动 | 外面套的重度 SLG 城建，与 demo 无关 |
| **智龙迷城 P&D** (2012) | 卡牌+消除+队伍的商业原型；羁绊/队伍技能的耦合方式 | 5 秒转珠的极限操作门槛，不适合休闲 |
| **神魔之塔** (2013) | 中文市场验证过的同类模型；卡牌养成深度 | 数值膨胀路径 |
| **Might & Magic: Clash of Heroes** (2009) | **上下分区回合制**的空间分配；"棋盘即战场"的紧张感 | 它是网格排布式，不是交换式三消 |
| **Crash Fever** (2016) | 二次元 + 极高密度演出；爽感节奏参考 | 日式扭蛋付费节奏 |
| **Puzzle Quest** (2007) | 三消+RPG 的祖源；技能消耗对应颜色能量 | 画面与节奏已过时 |
| **10000000 / You Must Build A Boat** | 单局短、连击正反馈、"消除直接换成长"的直接挂钩 | 像素美术风格 |
| **杀戮尖塔** | 局内构筑的经济模型：三选一、卡牌升级、遗物≈羁绊 | 与消除无关，只借经济结构 |

**结论性判断**：
- 布局和"消除→充能"的咬合，抄 **Marvel Puzzle Quest + Empires & Puzzles**。
- "上下分区"的空间语言，抄 **Clash of Heroes**。
- "爽感密度"，抄 **Crash Fever**。
- "局内构筑"，抄 **杀戮尖塔**。
- **"消除掉卡、局内养卡"是这套方案里唯一没有成熟对标的部分——这既是差异化，也是最大的风险点。**

品类现状要诚实说：**二次元 + 卡牌 + 三消在中文市场不是一个被验证过的大品类**。被验证的是"三消+SLG"（Puzzles & Survival）和"三消+家装"。所以这个 demo 的定位应该是**玩法探索**，而不是"抄一个已验证的赚钱模型"。

## 10. 技术方案（Egret Rebuild）

引擎已验证能力：2D 共享渲染（WebGPU/WebGL2）、Spine 4.3、粒子、2D 相机（含 shake/zoom）、Tiled 瓦片图、2D 音频混音、托管 UI、多语言文本。**本方案所需的全部能力都在已验证范围内，不需要等引擎新特性。**

### 10.1 模块划分
```
src/
  core/        Board.ts       纯数据棋盘（8×8 → 7×7 数组），无渲染依赖
               MatchResolver  消除判定 + 连锁求解，产出 MatchEvent[]
               Rng            可种子化随机（便于复现 bug）
  battle/      BattleFsm      回合状态机：PlayerPhase / EnemyPhase / Resolve
               EnergyPool     能量池，按色记账
               Deck           牌库/手牌/弃牌，抽牌与掉落
  card/        CardDef        卡牌数据（JSON 驱动）
               Synergy        羁绊判定
               Effects/       技能效果实现，统一接口 apply(ctx)
  view/        BoardView      订阅 MatchEvent 播放动画
               StageView      立绘 + Spine 播放
               FxQueue        演出队列，串行播放
  ui/          手牌/血条/倒计时/结算
data/          cards.json  synergies.json  stages.json
```

### 10.2 两个必须做对的工程点

**① 逻辑与表现彻底分离。**
`MatchResolver` 只吃棋盘状态、吐 `MatchEvent[]`（`{type:'clear', cells:[...], chain:2}`），不碰任何显示对象。`BoardView` 消费事件流播放动画。
不这么做的后果：连锁和演出会互相打架，改一个动画就崩判定，最后没法调。

**② 演出队列串行化。**
所有动画进 `FxQueue`，队列非空时锁定输入（但保留"下一张牌可预选"的高亮，避免手感发涩）。
不这么做的后果：玩家连点会把演出叠在一起，画面变成一团乱麻——这是同类 demo 最常见的崩坏点。

### 10.3 性能预算
- 棋盘 49 格 + 立绘 3-5 个 Spine + 粒子：在 Fold7 级别的机器上应该能稳 60fps
- 但引擎当前证据显示 Fold7 WebGL2 的帧间隔 p95 有 60-90ms 的记录（见 core-progress），**所以首版就要把粒子数量做成可配置**，并在设置里暴露"低特效"开关

## 12. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| **双玩法互相稀释** | 新手要同时学两套规则，30 秒内流失 | 前 2 关强制分步教学：第 1 关只有消除（自动攻击），第 2 关才解锁第一张卡 |
| **消除重复感** | 玩 10 分钟就腻 | 每关换棋盘规则：毒块 / 锁块 / 限色 / 传送门；Boss 战换棋盘尺寸 |
| **卡牌平衡爆炸** | 30 张卡 × 6 羁绊，组合数失控 | 羁绊只影响 2-3 张指定牌；不做通用百分比加成；数值表外置 JSON 便于快速调 |
| **立绘成本** | 二次元立绘 + Spine 极贵 | demo 用 4 个角色，先用代码绘制/AI 生成占位，验证玩法后再投入美术 |
| **爽感做不出来** | 机制对了但不好玩 | 把 60% 的工程预算花在反馈上（震动/粒子/音效/hitstop），而不是玩法复杂度 |
| **小屏棋盘误触** | 手机上交换失败 | 7×7 且单格 ≥ 64pt；拖动阈值 8px；支持"点选两格交换"作为备选操作 |

### 14.1 美术管线（2026-11-20 修订：代码绘制 + 可替换）

原计划用 AI 生成立绘，已验证可行（透明底 PNG 正常，1024×1536 RGBA，2.6MB）。但 AI 出的图是**整张位图，无法拆骨骼**，等于把演出能力锁死。改为代码绘制，并按 Spine 的槽位结构拆件出图。

**核心设计：部件清单就是合同。**

```
部件清单（bones / slots / parts）
        │
        ├─ 现在：占位绘制（代码画形状）→ 能跑、能演、能调
        └─ 将来：换 image 字段 → 接真实美术，骨骼与动画一行不改
```

所以清单里每个部件都必须声明：**挂在哪根骨、画在第几层、尺寸、轴心、旋转**。这五样定死之后，占位图和真美术是可互换的——这是"等做完了再改善品质"能成立的前提。

```json
{
  "id": "sword-blade",
  "bone": "hand-near",
  "layer": 19,
  "shape": "path",
  "size": [44, 600],
  "rotation": -145,
  "offset": [0, 0],
  "pivot": [0.5, 0.05],
  "color": "steel",
  "points": [[-0.5, -0.5], [0.5, -0.5], [0.5, 0.26], [0, 0.5], [-0.5, 0.26]],
  "image": null            // 将来填真实素材路径，其余字段不动
}
```

`shape` 有五种：`ellipse` / `rect` / `capsule` / `poly` 四种原始图形，加 `path`（归一化到 [-0.5, 0.5] 的任意轮廓，`smooth: true` 时用二次曲线穿过中点）。占位阶段够用了；真美术进来时 `shape`/`points` 全部失效，只剩 `size` 和 `pivot` 还有意义——它们决定 PNG 的像素尺寸和轴心位置。

**为什么用 offset 而不是绝对坐标**：Spine 的 attachment 是相对骨骼定位的。用 `bone + offset` 表达，占位图和真实骨骼的语义一致，转换时不需要重新推导。

**Spine 坐标转换**：清单用画布坐标（原点左上，y 向下）；Spine 用 y 向上。转换公式写进转换脚本，`spine_y = canvas.height - canvas_y`。

**分层顺序即绘制顺序**（`layer` 小的在背后）。后发在马尾前、马尾在身体后、远侧手臂在身体后、刀在近侧手之上——这套顺序就是 Spine 的 slot draw order。

**AI 那张图不浪费**：它现在是**美术方向参考**——配色（朱红 #e24b4a / 深红 #8f2320 / 金 #f0b45a）、服装结构（立领短打、金线滚边、红绸高马尾、缠火直刀）、以及将来给美术或模型改善品质时的 brief。占位图按这张图的剪影来画，风格不会跑偏。

### 14.2 部件清单（火 · 焰）

**16 根骨、40 个部件。** 清单在 `FivePhases/src/portrait/fire.mjs`，逐条明细见 `FivePhases/docs/PORTRAIT-PARTS.md`（由 `tools/parts-table.mjs` 从清单生成，不手写），预览页 `FivePhases/tools/portrait-preview.html`（`?bones=0` 隐藏骨骼、`?labels=1` 显示部件名、`?bg=0` 透明底）。

| 层组 | 部件 |
|---|---|
| 后层 | 后发、红绸飘带、左右衣摆、远侧上臂/肘/前臂/手 |
| 中层 | 衣身、腰带、近侧护肩/上臂/肘/前臂 |
| 前层 | 刀柄/刀镡/刀身/刀焰/刀头、近侧手、脖子、交领、头、眼白/瞳/高光/眼睑、双眉、嘴、前发、左右鬓发、双耳坠 |

三条从这一版里踩出来的规矩，已经写进工具：

- **四肢从骨骼算，不手填角度**。`limb()` 按两根骨的位置推长度和朝向，骨骼一动胳膊跟着走。手填 `rotation` 的话，每次挪骨都得重算一遍，一定会忘。
- **关节补一个同色圆**。两根胶囊在肘部交叠时会被掐出一个细腰，补一个同色圆就没了。
- **绘制顺序即 layer 顺序，且 layer 必须唯一**。Spine 的槽位顺序就是渲染顺序，重复了谁压谁全靠运气，所以 `lintPortrait()` 把重复当错误报。

导出链路已打通：

```
src/portrait/fire.mjs ──spine-export.mjs──▶ assets/spine/fire.skeleton.json  （Spine 4.1，导入即用）
                      └─parts-table.mjs──▶ docs/PORTRAIT-PARTS.md            （给美术的交付单）
```

`spine.mjs` 做双向转换，`spine.test.mjs` 用**往返测试**兜底：导出的骨架再读回来，骨骼位置、部件挂点、朝向、尺寸必须逐字段相等（11 例全过）。转换里丢一点东西，等美术交图、动画师开始 K 帧才会暴露，那时候改是灾难。

### 14.3 资产预算

| 项 | 数量 | 规格 |
|---|---|---|
| 角色 | 5（五行各一） | 每角色 16 骨 / 约 40 部件 |
| 卡面插画 | 30 张卡复用 5 张立绘 + 程序化构图 | 不做 30 张独立插画 |
| 元素方块 | 5 种形状 | 代码绘制，零加载 |
| 背景 | 1 张战斗背景 + 1 张模糊版 | 模糊版用于演出压暗层 |

**30 张卡不做 30 张插画**——这是成本控制的硬决策。卡面用「立绘裁切 + 元素底纹 + 程序化排版」组合，视觉上够用，且能保证风格绝对统一。

## 15. 待你决策的 4 个问题

1. **局内构筑 vs 局外养成**：本方案选"局内构筑"（单局 10 分钟）。如果你想要长线运营形态，得重做经济系统，工作量大 3 倍。
2. **角色数量**：demo 建议 4 个（1 主角 + 3 可招募），立绘成本可控。
3. **题材**：二次元是风格，题材还没定。东方仙侠 / 现代校园 / 蒸汽幻想，会影响卡牌命名和立绘方向。
4. **是否复用现有代码**：仓库里 `LanternShadows` 有 Spine + 瓦片 + 演出的成熟骨架，`LoveElective` 有 2D 分层视差和 UI 体系。抽哪个当起点能省不少时间。
